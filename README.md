# Паттерны проектирования на Python

[Открыть курс](web/index.html). **23 GoF-паттерна** и два дополнительных подхода: **Repository** и **Dependency Injection**. Python3.15+.

Примеры максимально абстрактны: роли паттерна, нейтральные значения и направление вызовов. Предметных сюжетов и бизнес-правил нет. В каждой главе две пары коротких фрагментов: основная операция и одно расширение. Варианты без паттерна и с паттерном дают одинаковый результат.

Три вкладки: **Объяснение**, **Примеры**, **Полная реализация**. Полные файлы расположены в двух колонках. Все файлы выбранных версий открыты сразу: сначала запуск, затем прямые зависимости и более глубокие участники.  Можно сравнивать **без паттерна / с паттерном**, выбирая базовый или расширенный пример, либо **без расширения / с расширением**, выбирая реализацию с паттерном или без него. Термины раскрываются, схема показывает связи, пояснения называют пользу и цену подхода. Простая функция может оказаться удобнее паттерна.

## Запуск

```sh
uv sync
uv run build-course
uv run test-course
uv run pytest
uv run python -m http.server 8000 --bind 127.0.0.1  # http://localhost:8000/web/
uv run python examples/strategy/python/with_pattern.py
uv run python examples/strategy/python/with_pattern_extended.py
uv run python examples/strategy/python/without_pattern.py
uv run pytest examples/strategy/python
```

Все команды выполняются из корня. Python выбирается через uv; другая версия задаётся `uv run --python 3.16 …`. `test-course` находит все темы и запускает каждую отдельным процессом. `pytest` без пути проверяет только `tests/`.

## Структура

- `web/`, `assets/` — интерфейс и сгенерированные ресурсы.
- `content/topics.json`, `content/guide-*.json` — главы и ссылки на исходники.
- `examples/<pattern>/python/` — ролевые модули, четыре запуска и тесты; связанные короткие реализации находятся вместе.
- `src/design_patterns/`, `tests/` — сборка и инфраструктурные проверки.
- `openspec/` — требования и история изменений.

`with_pattern.py` и `with_pattern_extended.py` запускают реализации с паттерном. `without_pattern.py` и `without_pattern_extended.py` — соответствующие исходные решения. Другие имена отражают роли: `context.py`, `component.py`, `creator.py`. Скачивание не требуется.

В расширенном режиме переключатель **Изменения** показывает diff относительно базового примера той же стороны: добавленные строки с `+`, удалённые с `−`. Кнопка копирования всегда берёт полный текущий файл без отметок diff.

Светлое и тёмное оформление адаптировано из [Verdandi / Verdandi Alter для VS Code](https://github.com/be5invis/vsc-theme-verdandi). Уведомление MIT сохранено в CSS; оттенки второстепенного текста усилены для читаемости.

После изменения исходников: `uv run build-course`. Проверка требований: `openspec validate --all --strict`.

## GitHub Pages и iOS

`uv run build-site` собирает сайт в `.build/site`. Для локальной проверки: `uv run python -m http.server 8000 --bind 127.0.0.1 --directory .build/site`. Откройте http://localhost:8000/. Исходный режим /web/ остаётся доступен, но офлайн-ресурсы создаются только build-site.

В репозитории GitHub выберите Settings → Pages → Source → GitHub Actions. Workflow публикует ветку main и допускает ручной запуск. Для репозитория design-patterns адрес имеет вид https://dmitriiskniazev.github.io/design-patterns/.

На iPhone/iPad откройте адрес в Safari → Поделиться → На экран «Домой» → Открывать как веб-приложение. Дождитесь надписи «Курс доступен офлайн». После этого локальные материалы и код доступны без сети; внешние источники требуют интернета. Система может очистить кеш при нехватке места — тогда снова откройте курс онлайн.

Место чтения сохраняется на устройстве; ссылка с явно указанным разделом имеет приоритет. Синхронизации между устройствами нет. Загруженное обновление применяется после закрытия всех окон курса и повторного открытия.
