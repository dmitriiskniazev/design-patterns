# Repository Guidelines

## Назначение проекта

Русскоязычный курс паттернов проектирования для подготовки к собеседованиям. Пользователь уверенно пишет на Python. Курс и примеры пишите только на Python >=3.15. Объяснения должны быть короткими, точными и связанными с работающим кодом.

## Структура

- `web/index.html` — шаблон входа в курс; готовый сайт находится в `.build/site/`.
- `web/src/` — адаптер курса: navigation, lesson, code_viewer и миграция settings.
- `pyproject.toml` и `uv.lock` фиксируют полный Git SHA course-engine с общими ресурсами, шрифтами и лицензиями.
- `web/lessons.json` — теория, задания, вопросы и ссылки на источники.
- `examples/<pattern>/{base,extended}/{without_pattern,with_pattern}/` — реализации и проверки.
- `src/design_patterns/` — пакет сборки и проверки курса.
- `tests/` — инфраструктурные pytest-проверки.
- `pyproject.toml`, `uv.lock` — проект uv и зафиксированные зависимости.
- `openspec/` — требования, планы, задачи и история изменений.

`.build/site/course-data.js` генерируется сборщиком и не хранится в Git; каталог тем поставляет установленный `course-engine`; сборщик создаёт CSS палитр и Pygments-подсветки в готовом сайте. Меняйте исходники и пересобирайте их через `uv run build-course`.

## Команды

```sh
uv sync
uv run --directory examples/strategy python -m pattern.main
uv run python examples/adapter/base/with_pattern/main.py
uv run python -m http.server 8000 --bind 127.0.0.1 --directory .build/site  # http://localhost:8000/
uv run test-course
uv run pytest
uv run test-course adapter
uv run pytest examples/adapter/base/with_pattern
uv run build-course
```

Проект использует `uv`, `pyproject.toml`, `uv.lock`, пакет в `src/` и проверки в `tests/`. Все Python-команды запускайте через `uv run`; Python 3.15 выбран в `.python-version`, минимальная версия задана в `pyproject.toml`. Другую версию задавайте через `uv run --python 3.16 …`. `uv run test-course` проверяет инфраструктуру и автоматически находит варианты, запуская каждый отдельным процессом с остановкой при ошибке. `uv run pytest` проверяет только `tests/`; для одной темы укажите её путь. ZIP-комплекты не создаются. После копирования файлов примеры запускаются автономно через `uv run --no-project --python 3.15`, тесты добавляют `--with pytest python -m pytest`.

## Учебные материалы и код

Все25 тем показывают только абстрактную механику паттерна. Используйте роли Context, Strategy, Subject, Receiver, Component и другие по смыслу; раскрывайте их термины. Не вводите игры, документы, звук, датчики, часы, SQL и другую предметную модель. Нейтральные значения1/A/B показывают результат вызова. Не добавляйте бизнес-правила и валидацию ради объёма примера.

В каждой главе две пары коротких фрагментов: одна операция и одно расширение. Фрагмент — до12 непустых строк, извлекается из исполняемого исходника. До и после одинаковы вход, возможности и результат. Показывайте путь вызова, изменяемую часть, стабильных участников и цену абстракции; не обещайте преимущество короткому примеру, если обычная функция проще.

Все темы имеют fileComparison с четырьмя автономными каталогами: base/without_pattern, base/with_pattern, extended/without_pattern, extended/with_pattern внутри examples/<pattern>/. В каждом main.py, необходимые ролевые модули и test_example.py. Уровня python нет. Импорты между вариантами запрещены. Повторение неизменившихся маленьких модулей допустимо; базовые файлы не содержат участников расширения заранее. Интерфейс имеет два режима «Разбор» и «Код». Разбор показывает цельные короткие сравнения, схемы и роли раскрываются по запросу. Код занимает доступную высоту окна: одна выбранная смысловая пара baseline/pattern, список обязанностей вместо каталога глав, реальные пути над кодом, выровненные строки и общая вертикальная прокрутка. Этап основной/расширенный выбирается одним селектором. На узкой области — выбор файла и переключатель стороны с сохранением позиции. Идентичный общий файл показан один раз. Пары guide.filePairs задаются явно по смыслу, допускают повторение файла; все исходники должны быть достижимы. Различия включены по умолчанию, копируется точный исходник. Команды и метаданные — в «Действиях». Код не требует скачивания.

Используйте четыре пробела, ясные имена, явные типы, dataclass и Protocol по необходимости. Закрытый выбор — StrEnum и match, свободные маркеры результата — строки. Не уплотняйте код точками с запятой и однострочными телами ради числа строк. Имена файлов отражают роли, например context.py, component.py, creator.py. Тесты test_*.py проверяют существенное свойство и одинаковый результат обеих версий; каждый вариант запускается pytest отдельным процессом.

## Работа с изменениями

Существенные изменения ведите через OpenSpec. Перед работой прочитайте `openspec/config.yaml` и соответствующие спецификации. Обновляйте задачи после реализации и проверки; завершённые изменения синхронизируйте и архивируйте. Проверяйте `openspec validate --all --strict`.

## Проверка и порядок

Для кода запускайте соответствующие тесты; для интерфейса проверяйте выбор темы и шага, подсветку, ссылки, клавиатуру и узкий экран. Указывайте фактические результаты и непроверенные условия.

Сохраняйте в корне только README и AGENTS из Markdown-документов. Дополнительные пакеты, конфигурации тестовых инструментов и служебные документы добавляйте только по запросу. Внешние средства проверки держите вне проекта. При перемещении файлов обновляйте ссылки; перед удалением авторских материалов сохраняйте резервную копию.

## Согласованный пилот Abstract Factory

Для examples/abstract_factory действуют новые правила, заменяющие требования выше об абстрактных маркерах и четырёх автономных копиях: snake_case, baseline/ и pattern/, общие interfaces.py и formats/{json,yaml,toml}.py, общий test_example.py. Интерфейсы Reader/Writer/SerializationFactory — Protocol; реализации без наследования. Используются настоящие json, PyYAML, tomllib, tomli-w; вход dict[str, str], клиент write_and_read. Фабрики только в pattern/factories.py. Самостоятельная единица копирования — вся папка паттерна. Запуск из неё: uv run python -m baseline.main либо uv run python -m pattern.main. Проверка из корня: uv run test-course abstract_factory. Обе версии включают три формата; TOML объясняется фрагментами кода без base/extended и без фиктивного diff снимков. Идентификатор главы abstract-factory сохраняется для старых URL. Остальные главы мигрируются отдельно.

Пилот Abstract Factory также реализует второй вид расширения — Validator для JSON/YAML/TOML. Protocol Validator и create_validator добавлены во все фабрики; validate_and_read проверяет внешний текст перед чтением, прежний write_and_read сохраняется. Общая проверка словаря строк находится в validation.py. Эта глава имеет три парных сравнения: основная операция, новое семейство и новый тип продукта. Отдельный Validator — запрошенное расширение, а не произвольная валидация ради объёма; в тексте явно объясняется двойной разбор входа.

## Согласованный пример Strategy

Strategy использует examples/strategy/{baseline,pattern}/ и общий test_example.py вместо четырёх автономных снимков. baseline/{operations,context,main}.py: frozen dataclass Add(amount), Multiply(factor), Constant(value), закрытое объединение типов и match. pattern/{interfaces,strategies,context,main}.py: Strategy(Protocol).apply(int)->int, реализации без наследования, mutable Context(strategy) с apply_all(list[int])->list[int]. Обе main показывают настройку и замену операции у одного Context, входной список не меняется. В тесте проверяется внешний тип без наследования. Копируется вся папка Strategy; запуск из неё через uv run python -m baseline.main или pattern.main. Constant объясняется вторым коротким сравнением по конечным исходникам; отдельные base/extended не создаются. Изменение контракта объясняется текстом. Остальные главы мигрируются отдельно.

## Интерфейс и настройки

`web/src` хранит адаптер курса: навигацию, renderer уроков, смысловые пары и миграцию `patterns.*`. Общие настройки, панель, темы, девять локальных шрифтов с лицензиями, копирование, декорирование и CSS поставляет установленный `course-engine`. Не восстанавливайте их копии в авторских каталогах. Сборка накладывает ресурсы пакета в `.build/site` и создаёт полный офлайн-снимок с прежним префиксом `patterns:` и scope. Исходники и настройки работают через HTTP или установленную офлайн-копию, не file://.

Изменения общего оформления выполняйте в движке и проверяйте на обоих курсах. Обновление: после проверки нового коммита движка выполнить `uv add "course-engine @ git+https://github.com/dmitriiskniazev/course-engine" --rev <full-sha>` и сохранить `pyproject.toml` и `uv.lock` вместе с адаптером. Не добавляйте зависимость CI от `../course-engine`. Новые шрифты требуют лицензий и проверки кириллицы/начертаний; font-synthesis отключён. Курс сохраняет `uv run build-course`, `test-course`, `pytest`, старые маршруты и точный учебный код. `app.js` связывает модули явными импортами.

Имена файлов и каталогов интерфейса — snake_case. Defaults/normalize, применение, панель и импорт VS Code находятся в пакете; новые параметры должны одинаково поддерживаться нормализацией, панелью, сохранением и импортом при наличии аналога VS Code. CSS хранится рядом с функциональностью; общие layout и токены поставляет движок. Каталог тем один, без скрытых наборов цветов.
