# Repository Guidelines

## Назначение проекта

Русскоязычный курс паттернов проектирования для подготовки к собеседованиям. Пользователь уверенно пишет на Python. Курс и примеры пишите только на Python >=3.15. Объяснения должны быть короткими, точными и связанными с работающим кодом.

## Структура

- `web/index.html` — вход в курс.
- `assets/app.js`, `assets/app.css` — интерфейс и его оформление.
- `content/topics.json` — теория, задания, вопросы и ссылки на источники.
- `examples/<pattern>/python/` — реализации и проверки.
- `src/design_patterns/` — пакет сборки и проверки курса.
- `tests/` — инфраструктурные pytest-проверки.
- `pyproject.toml`, `uv.lock` — проект uv и зафиксированные зависимости.
- `openspec/` — требования, планы, задачи и история изменений.

`assets/course-data.js` генерируется сборщиком; `assets/highlight.css` задаёт цвета подсветки для обеих тем страницы. Меняйте исходники и пересобирайте их через `uv run build-course`.

## Команды

```sh
uv sync
uv run python examples/strategy/python/with_pattern.py
uv run python examples/adapter/python/with_pattern.py
uv run python -m http.server 8000 --bind 127.0.0.1  # http://localhost:8000/web/
uv run test-course
uv run pytest
uv run pytest examples/adapter/python
uv run build-course
```

Проект использует `uv`, `pyproject.toml`, `uv.lock`, пакет в `src/` и проверки в `tests/`. Все Python-команды запускайте через `uv run`; Python 3.15 выбран в `.python-version`, минимальная версия задана в `pyproject.toml`. Другую версию задавайте через `uv run --python 3.16 …`. `uv run test-course` проверяет инфраструктуру и автоматически находит темы, запуская каждую отдельным процессом с остановкой при ошибке. `uv run pytest` проверяет только `tests/`; для одной темы укажите её путь. Учебные ZIP-комплекты используют автономные команды `uv run --no-project --python 3.15`, тесты добавляют `--with pytest python -m pytest`.

## Учебные материалы и код

Все25 тем показывают только абстрактную механику паттерна. Используйте роли Context, Strategy, Subject, Receiver, Component и другие по смыслу; раскрывайте их термины. Не вводите игры, документы, звук, датчики, часы, SQL и другую предметную модель. Нейтральные значения1/A/B показывают результат вызова. Не добавляйте бизнес-правила и валидацию ради объёма примера.

В каждой главе две пары коротких фрагментов: одна операция и одно расширение. Фрагмент — до12 непустых строк, извлекается из исполняемого исходника. До и после одинаковы вход, возможности и результат. Показывайте путь вызова, изменяемую часть, стабильных участников и цену абстракции; не обещайте преимущество короткому примеру, если обычная функция проще.

Все темы имеют fileComparison с четырьмя автономными наборами: without_pattern.py, with_pattern.py, without_pattern_extended.py, with_pattern_extended.py и их ролевые зависимости. Файлы лежат в examples/<pattern>/python/ без дополнительных уровней before/after. Полные файлы читаются в двух колонках: без/с паттерном с выбором базового или расширенного примера либо без/с расширением с выбором реализации без паттерна или с ним. Все файлы выбранных версий открыты сразу: сначала запуск, затем прямые зависимости и более глубокие участники. Код не требует скачивания. Интерфейс: «Объяснение», «Примеры», «Полная реализация».

Используйте четыре пробела, ясные имена, явные типы, dataclass и Protocol по необходимости. Закрытый выбор — StrEnum и match, свободные маркеры результата — строки. Не уплотняйте код точками с запятой и однострочными телами ради числа строк. Имена файлов отражают роли, например context.py, component.py, creator.py. Тесты test_*.py проверяют существенное свойство и одинаковый результат обеих версий; каждая тема запускается pytest отдельным процессом.

## Работа с изменениями

Существенные изменения ведите через OpenSpec. Перед работой прочитайте `openspec/config.yaml` и соответствующие спецификации. Обновляйте задачи после реализации и проверки; завершённые изменения синхронизируйте и архивируйте. Проверяйте `openspec validate --all --strict`.

## Проверка и порядок

Для кода запускайте соответствующие тесты; для интерфейса проверяйте выбор темы и шага, подсветку, ссылки, клавиатуру и узкий экран. Указывайте фактические результаты и непроверенные условия.

Сохраняйте в корне только README и AGENTS из Markdown-документов. Дополнительные пакеты, конфигурации тестовых инструментов и служебные документы добавляйте только по запросу. Внешние средства проверки держите вне проекта. При перемещении файлов обновляйте ссылки; перед удалением авторских материалов сохраняйте резервную копию.
