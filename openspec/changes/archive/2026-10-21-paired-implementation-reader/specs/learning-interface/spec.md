## MODIFIED Requirements

### Requirement: Собранный код доступен для чтения
Во вкладке «Полная реализация» пользователь MUST видеть две реализации: без паттерна и с паттерном. Общий переключатель MUST выбирать базовый пример или расширение; файлы каждой стороны MUST выбираться независимо и принадлежать выбранному режиму. Код MUST совпадать с исходником; номера строк MUST NOT попадать в копирование. Прямая ссылка и история MUST сохранять режим и оба файла; прежние vN-ссылки MUST работать. Одинаковый выбранный полный файл MUST показываться один раз с явной подписью. На узком экране колонки MUST располагаться последовательно.

#### Scenario: Чтение итогового файла
- **WHEN** пользователь выбирает просмотр собранного кода
- **THEN** видит состав выбранной версии, назначение выбранного файла и его полный код в одной области

#### Scenario: Сохранение постепенного формата
- **WHEN** пользователь открывает шаг без выбора полного файла
- **THEN** во вкладке примеров отображаются короткие фрагменты, а полные файлы остаются скрытыми

### Requirement: Связи полного исходника
Область полного кода MUST объяснять назначение файла и предоставлять переходы к его импортируемым локальным файлам выбранной версии. При смене режима MUST выбираться существующие файлы каждой стороны; исходный файл naive.py MUST заменяться файлом расширения before_extension.py, если он был выбран по умолчанию. Некорректные значения URL MUST NOT приводить к пустому экрану. Список и код MUST помещаться в ширину страницы, допуская локальную прокрутку.

#### Scenario: Чтение Strategy
- **WHEN** пользователь открывает полную реализацию с паттерном
- **THEN** сначала видит main.py и может перейти в wiring.py, затем Enemy и контракт, не раскрывая список всех исходников

#### Scenario: Восстановление ссылки
- **WHEN** открывается ссылка на версию и файл
- **THEN** выделен соответствующий файл и показан его точный исходник; отсутствующий файл заменяется входным

## ADDED Requirements

### Requirement: Точные наборы сравнения
Все25 тем MUST предоставлять четыре явно различимых набора: базовый без паттерна, базовый с паттерном, расширенный без паттерна и расширенный с паттерном. Наборы исходного решения MUST включать транзитивные локальные зависимости и MUST NOT смешивать посторонние файлы другого режима. Реестр общих исходников MUST оставаться дедуплицированным.

#### Scenario: Расширение Decorator
- **WHEN** выбран режим расширения
- **THEN** слева доступен before_extension.py и его naive.py, справа — extended.py и обработка ClipLimit

#### Scenario: Общий файл
- **WHEN** обе стороны выбрали одинаковый исходник
- **THEN** виден один полный текст с указанием его общности, а выбор файлов обеих сторон остаётся доступен
