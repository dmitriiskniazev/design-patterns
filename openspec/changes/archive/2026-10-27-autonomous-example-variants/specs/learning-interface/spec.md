## MODIFIED Requirements

### Requirement: Понятные имена учебных файлов
Все25 тем MUST использовать имена ролевых модулей, раскрывающие их содержимое и обязанность. Файлы расширений MUST NOT называться extra.py. Все входы MUST называться main.py; этап и реализация MUST задаваться каталогами base/extended и without_pattern/with_pattern. Переименование MUST обновлять импорты, команды, подписи и ссылки на исходники; прежние имена в ссылках полной реализации MUST открывать соответствующий переименованный файл без дополнительных файлов-обёрток.

#### Scenario: Чтение состава примера
- **WHEN** читатель выбирает файл полной реализации любой темы
- **THEN** его имя описывает обязанность роли либо однозначно обозначает сторону сравнения и базовый или расширенный запуск

#### Scenario: Прежнее имя
- **WHEN** ссылка полной реализации содержит прежнее имя переименованного файла
- **THEN** открывается тот же файл под актуальным именем

### Requirement: Точные наборы сравнения
Все25 тем MUST предоставлять четыре явных набора с полным замыканием локальных импортов. Каждый набор MUST читаться из собственного автономного каталога, без наложения базовых файлов или импортов другой стороны. Реестр одинаковых исходников MUST быть дедуплицированным.

#### Scenario: Расширение Decorator
- **WHEN** подключается новый декоратор
- **THEN** видны новый участник, сборка вложения и прежний контракт Component

#### Scenario: Общий файл
- **WHEN** обе стороны содержат одинаковый полный файл с одинаковым представлением diff и совместимым порядком
- **THEN** его исходник отображается один раз на общей строке сравнения

### Requirement: Минимальный учебный пример
Каждая глава MUST показывать механику паттерна и одно расширение двумя короткими парными сравнениями. Запуск MUST использовать нейтральные значения и минимум действий, необходимых для свойства паттерна. Бизнес-логика и произвольная валидация MUST отсутствовать. Читаемость и явные типы MUST сохраняться; разделение файлов MUST помогать пониманию обязанности или зависимости, а связанные короткие реализации MAY оставаться вместе.

#### Scenario: Чтение короткого примера
- **WHEN** открыта вкладка примеров
- **THEN** видны ровно две пары: основная операция и одно расширение

#### Scenario: Минимальный запуск
- **WHEN** открыт main.py варианта с паттерном
- **THEN** нейтральные значения показывают только существенные вызовы паттерна
