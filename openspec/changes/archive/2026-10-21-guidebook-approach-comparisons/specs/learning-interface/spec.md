## MODIFIED Requirements

### Requirement: Сравнение решений в основном курсе
Strategy, Adapter, State, Observer, Command, Composite и Decorator MUST показывать guide book с формальной постановкой, схемами участников, конкретным вызовом, парными короткими фрагментами различий, направлениями роста и ценой подходов. Общие модели и повторяющиеся файлы MUST NOT дублироваться в основном сравнении. Полные исходники MUST быть доступны в закрытых по умолчанию раскрытиях и повторяться только как ссылки на один текст. На широком экране варианты MUST быть рядом, на узком последовательно. Фрагменты MUST извлекаться из исполняемых исходников; глава MUST явно отличать дополнительные иллюстрации применения от запускаемого примера. Основной вход web/index.html MUST показывать этот формат без скачивания.

#### Scenario: Обычный вход
- **WHEN** читатель выбирает одну из семи guide-тем
- **THEN** сначала видит задачу и рисунки, затем различия подходов в коротких исходных фрагментах; полные файлы скрыты

#### Scenario: Сравнение реализации
- **WHEN** читатель сравнивает варианты
- **THEN** одинаковые элементы не отвлекают от различий, а имя файла и извлечённый фрагмент показывают место изменения

#### Scenario: Расширение
- **WHEN** читатель изучает расширяемость
- **THEN** видит несколько осей роста, неизбежные изменения подключения и проверки, а также случай, когда простой вариант удобнее

### Requirement: Разделы и постоянные ссылки
Интерфейс MUST вести читателя по единой последовательности: задача и мотивация, базовое решение по шагам, самостоятельная практика, расширенное решение по шагам, следующая готовая тема. На каждом экране MUST быть один следующий переход и обратный переход, кроме границ курса. Прогресс MUST показывать положение в этой последовательности. Вкладки разделов, список переходов между шагами и переходы из схемы MUST NOT конкурировать с основным чтением. Прямые ссылки MUST сохранять тему, раздел и шаг; история браузера MUST работать. Выбор темы в каталоге MUST открывать её начало. Strategy, Adapter, State, Observer, Command, Composite и Decorator MUST показывать одну guide-главу в основном курсе; ссылки прежних кода, практики и расширения MUST вести в соответствующую часть этой страницы.

#### Scenario: Возврат к разделу
- **WHEN** открывается ссылка готового урока или используется история браузера
- **THEN** восстанавливаются выбранные тема и место чтения; в семи guide-главах шаг соответствует смысловой части полной страницы

#### Scenario: Ошибочная ссылка
- **WHEN** идентификатор темы или формат ссылки некорректен
- **THEN** интерфейс открывает доступный материал Strategy без ошибки выполнения

#### Scenario: Конец расширения
- **WHEN** пользователь завершает последний шаг расширения
- **THEN** следующий переход открывает начало следующей готовой темы, а после последней темы показано завершение курса без возврата к практике

#### Scenario: Начало другой темы
- **WHEN** пользователь выбирает другую тему из каталога, находясь на шаге расширения
- **THEN** открывается постановка новой темы, а не расширение

### Requirement: Постепенное представление кода
Каждый готовый урок MUST вводить конструкции через последовательность шагов: короткое пояснение, листинг не длиннее 12 непустых строк и объяснение результата. В пошаговых темах на экране MUST отображаться один шаг с навигацией назад и вперёд. Strategy, Adapter, State и Observer MUST показывать полные именованные файлы сравнения, включая импорты и запуск. Ограничение 12 строк относится к объясняющим фрагментам, а не к полным файлам. Интерфейс MUST NOT требовать скачивания.

#### Scenario: Чтение по шагам
- **WHEN** пользователь открывает код и переходит к следующему шагу
- **THEN** в пошаговой теме отображается следующий короткий листинг; в guide-главе видны короткие фрагменты различий, а полные файлы скрыты под раскрытием

#### Scenario: Отдельный исполняемый файл
- **WHEN** пользователь копирует файлы полного примера
- **THEN** получает исполняемый набор с импортами и точкой запуска

### Requirement: Собранный код доступен для чтения
Пользователь MUST иметь возможность посмотреть полный итоговый комплект Python-файлов на странице отдельно от коротких шагов. Показанный текст MUST совпадать с соответствующим файлом исполняемого комплекта; код MUST соответствовать предметной теме урока и поддерживать локальное чтение. В пошаговых темах полный код MUST открываться по выбору пользователя. В guide-главах полный код MUST открываться по выбору пользователя; одинаковые файлы MUST показываться один раз со ссылками из состава версий. Интерфейс MUST NOT предлагать скачивание.

#### Scenario: Чтение итогового файла
- **WHEN** пользователь выбирает просмотр собранного кода
- **THEN** видит полные файлы под раскрытием, включая guide-главы

#### Scenario: Сохранение постепенного формата
- **WHEN** пользователь открывает шаг без выбора полного файла
- **THEN** отображаются короткие фрагменты, а полные файлы остаются скрытыми

### Requirement: Последовательное изложение урока
В пошаговых темах теория MUST излагаться одной колонкой в порядке: задача, простое решение, новое требование, идея паттерна, участники и путь вызова, условия применения и цена. Схема MUST следовать после мотивации, не повторяться на каждом базовом шаге и не вводить переходов между шагами. Дублирующий список ролей и предварительный первый листинг MUST NOT разрывать этот порядок. Каждый экран пошаговой темы MUST сохранять один короткий листинг и пояснение. В семи guide-главах MUST последовательно показываться задача, схема вызова, различия реализаций, направления роста и условия применения. Итоговый комплект и просмотр полных файлов MUST предлагаться после последнего шага соответствующего разбора.

#### Scenario: Первое чтение любой темы
- **WHEN** пользователь последовательно проходит готовый урок
- **THEN** сначала узнаёт задачу; затем проходит шаги в пошаговой теме или сравнивает две реализации и их расширения в теме сравнения

#### Scenario: Прямой вход в код
- **WHEN** пользователь открывает первый базовый или расширенный шаг по ссылке
- **THEN** видит постановку перед текущим листингом; дальнейший переход продолжает общий порядок

## ADDED Requirements

### Requirement: Проверяемая guide-глава
Сборка MUST извлекать каждый сравниваемый фрагмент из существующего Python-файла, ограничивать его 12 непустыми строками, проверять ссылки схем и сохранять все полные файлы с указанием вариантов использования. SVG MUST иметь доступное текстовое описание. Guide-главы MUST сохранять последовательную навигацию между темами и совместимость прежних ссылок.

#### Scenario: Недостоверный фрагмент
- **WHEN** selector не найден, путь выходит из проекта или схема ссылается на неизвестный узел
- **THEN** сборка завершается ошибкой вместо публикации недостоверного сравнения
