# Design

## Context
Сборщик выполняет работу при импорте, а Makefile изолирует pytest-процессы для тем с одинаковыми именами модулей. См. proposal.md.

## Goals / Non-Goals
**Goals:** устанавливаемый src-пакет, фиксированные зависимости, тестируемая сборка и общая команда проверки.
**Non-Goals:** переименование модулей учебных примеров и изменение интерфейса.

## Decisions
- src/design_patterns/build.py содержит build(root), extract и точку входа main. Импорт не создаёт артефактов. Корень определяется текущим рабочим каталогом, а не расположением установленного пакета.
- pyproject.toml использует uv_build, Pygments как зависимость сборщика и pytest в группе dev. Команды build-course и test-course запускаются через uv run.
- test-course сначала проверяет tests, затем каждый каталог examples/*/python отдельным процессом sys.executable -m pytest; первая ошибка возвращается вызывающему процессу.
- Примеры остаются самостоятельными учебными комплектами; их команды с --no-project сохраняются для ZIP. Перенос их в один пакет усложнил бы автономное чтение и запуск.

## Risks / Trade-offs
- Одинаковые имена модулей → отдельные процессы для тем.
- Первый запуск требует загрузки зависимостей → uv.lock и явная фиксация Python >=3.15.

## Migration Plan
Сохранить Makefile и сборщик вне проекта, добавить пакет и тесты, обновить инструкции, проверить сборку и все темы, синхронизировать требования и архивировать изменение. Резервные копии позволяют вернуть старые файлы.
