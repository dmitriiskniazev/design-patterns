# Spec Delta

## MODIFIED Requirements

### Requirement: Разбор расширенных заданий
Каждая готовая тема MUST предоставлять отдельный пошаговый разбор расширения на Python. Разбор MUST показывать новое требование, конкретное усложнение варианта до паттерна, реализацию после паттерна, стабильные части и изменения, которые всё равно необходимы. Расширение MUST использовать тот же формат коротких листингов до 12 непустых строк и не подменять структурную расширяемость утверждениями о скорости выполнения.

#### Scenario: Из упражнения к разбору
- **WHEN** пользователь выбирает разбор расширения из задания
- **THEN** открывается первый шаг соответствующей расширенной задачи, а полное решение не показывается сплошным листингом

#### Scenario: Сравнение до и после
- **WHEN** пользователь проходит расширение Strategy, Adapter или State
- **THEN** видит рост общего списка вариантов или переходов, затем изолированное новое поведение и точное описание оставшихся изменений

#### Scenario: Исполнение расширения
- **WHEN** запускаются расширенные варианты и проверки
- **THEN** подтверждаются охрана точки с прежним контекстом Strategy, второй звуковой API с прежним клиентом Adapter и пауза проигрывателя State

### Requirement: Содержательные учебные задачи
Готовые уроки MUST использовать примеры с небольшими узнаваемыми задачами и минимальными предметными правилами. Теория и разбор MUST объяснять, какие новые требования мотивируют паттерн, какие части решения сохраняются и какие допущения ограничивают учебную модель. Локальные имитации внешних систем MUST быть обозначены явно.

#### Scenario: Изучение рабочего сценария
- **WHEN** пользователь читает готовый урок и его расширение
- **THEN** видит условия применения правил, результат на конкретных данных и поведение при недопустимом действии

#### Scenario: Проверка границ
- **WHEN** запускаются проверки примеров
- **THEN** проверяются существенные свойства паттернов и границы соответствующих задач: ход противника, единицы громкости API и запрещённые события проигрывателя

### Requirement: Постановка до обсуждения паттерна
Готовый урок MUST начинаться с цели прикладной задачи, исходных данных или событий, правил и конкретного примера ожидаемого результата. Затем MUST объясняться простое решение, усложнение при новых требованиях и идея паттерна. Первые листинги и роли паттерна MUST следовать после постановки задачи.

#### Scenario: Первое чтение State
- **WHEN** пользователь открывает теорию State
- **THEN** до обсуждения изменений кода видит задачу управления проигрывателем, правила запуска/остановки/паузы и пример допустимого или запрещённого события

#### Scenario: Прямой вход в разбор
- **WHEN** пользователь открывает первый шаг базового или расширенного решения
- **THEN** перед листингом видит соответствующую задачу с правилами и примером результата

#### Scenario: Статический урок
- **WHEN** пользователь открывает статический урок Strategy
- **THEN** до первых листингов видит постановку задачи выбора следующего хода игрового противника

### Requirement: Прозрачный путь адаптации
Разбор Adapter MUST объяснять воспроизведение звука через исходный контракт SDK, ожидаемый контракт приложения, вызов клиента и роль адаптера. Подробности преобразования MUST следовать после объяснения пути вызова. Каждый вводимый участник MUST иметь конкретную обязанность и понятный результат.

#### Scenario: Сквозной пример
- **WHEN** пользователь читает базовый разбор Adapter
- **THEN** прослеживает вызов play с громкостью 0.5, вызов старого SDK с громкостью 50 процентов и возврат результата клиенту

### Requirement: Собранный код доступен для чтения
Пользователь MUST иметь возможность посмотреть полный итоговый комплект Python-файлов на странице отдельно от коротких шагов. Показанный текст MUST совпадать с соответствующим файлом скачиваемого исполняемого комплекта; код MUST соответствовать предметной теме урока и поддерживать локальное чтение. Полный код MUST показываться по явному выбору пользователя.

#### Scenario: Чтение итогового файла
- **WHEN** пользователь выбирает просмотр собранного кода
- **THEN** видит файлы соответствующего решения, их обязанности и подсвеченный код выбранного файла и может вернуться к коротким фрагментам

#### Scenario: Сохранение постепенного формата
- **WHEN** пользователь открывает шаг без выбора полного файла
- **THEN** отображается один короткий листинг с контекстом, а полный код файлов не показывается автоматически

### Requirement: Ограниченная предметная область
Каждый урок MUST использовать подходящую паттерну узнаваемую задачу. Strategy MUST показывать поведение игрового противника, Adapter — согласование звуковых API, State — проигрыватель, Command — редактор с отменой, Observer — датчики станции, Composite — дерево игровой сцены, Decorator — звуковые эффекты. Каждый разбор MUST ограничивать дополнительные предметные правила теми, которые непосредственно объясняют паттерн. Расширение MUST добавлять одну возможность. Файлы данных, реализации и запуска MUST быть разделены по обязанностям и доступны для чтения в комплекте.

#### Scenario: Общая тема без лишних правил
- **WHEN** пользователь изучает три готовых урока
- **THEN** видит разные небольшие задачи и понимает выбор поведения противника, согласование звуковых API и состояния проигрывателя без посторонних предметных процессов

#### Scenario: Чтение и запуск файлов
- **WHEN** пользователь выбирает полный пример или скачивает его
- **THEN** может переключать файлы с указанными обязанностями и получает все файлы, необходимые для документированной uv-команды

### Requirement: Полнота учебного набора
Каждая тема MUST предоставлять исполняемое базовое и расширенное решение, краткие листинги не длиннее12 непустых строк, схему участников и путь вызова, упражнение и вопрос для собеседования. Расширение MUST показывать конкретное усложнение до паттерна, изолированное изменение после и границы выигрыша. Реализации MUST демонстрировать свойство соответствующего паттерна и минимальные правила выбранной предметной задачи.

#### Scenario: Самостоятельный запуск комплекта
- **WHEN** пользователь скачивает ZIP базового или расширенного решения и распаковывает его отдельно
- **THEN** документированная uv-команда и включенные pytest-проверки работают без файлов репозитория

#### Scenario: Проверка существенного свойства
- **WHEN** запускаются тесты каждой темы
- **THEN** проверяется соответствующее свойство паттерна: совместимость семейства, независимость копий или обходов, восстановление, разделение данных, диспетчеризация или подмена зависимости
