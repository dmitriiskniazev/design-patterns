# Spec Delta

## ADDED Requirements

### Requirement: Прозрачный путь адаптации
Разбор Adapter MUST объяснять один конкретный платёж через исходные данные поставщика, ожидаемые данные приложения, вызов клиента и роль адаптера. Подробности валидации и преобразования MUST следовать после объяснения пути вызова. Каждый вводимый участник MUST иметь конкретную обязанность и понятный результат.

#### Scenario: Сквозной пример
- **WHEN** пользователь читает базовый разбор Adapter
- **THEN** видит, как строковая сумма 19.99 и статус completed превращаются в 1999 минимальных единиц и paid, какой вызов делает клиент и какой вызов делает адаптер к SDK

### Requirement: Строгая граница внешних данных
Примеры адаптации MUST отклонять отсутствующие обязательные поля, неверные типы, неизвестные валюты и статусы до передачи данных клиенту. Десятичные суммы MUST сохранять точность; правила для неподдерживаемой точности MUST быть явными. Зависимости MUST подхватываться при документированном запуске через uv.

#### Scenario: Некорректный ответ
- **WHEN** SDK возвращает число вместо ожидаемой строки, строку или bool вместо целой суммы/кода, неподдерживаемую валюту либо неизвестный статус
- **THEN** получение квитанции завершается ошибкой, а данные не выдаются как успешная оплата

#### Scenario: Проверка полного примера
- **WHEN** базовый или расширенный файл Adapter запускается документированной uv-командой
- **THEN** зависимость проверки схемы доступна и вывод соответствует разобранному платежу
