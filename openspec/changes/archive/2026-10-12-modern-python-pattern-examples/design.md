# Design

## Ответственность кода
match делает выбор события наглядным, но не заменяет State: реакция каждой фазы остаётся в её объекте. Event нормализует строки на входе; dataclass Order использует отдельную фабрику начального состояния. Checkout хранит тариф через dataclass без ручного конструктора.

Receipt — неизменяемая внутренняя dataclass с Literal-контрактами. Pydantic применяется только к внешнему ответу. LegacyPayment проверяет словарь, GatewayPayload читает атрибуты стороннего объекта; strict не разрешает неявную подмену типов. Перевод сумм и статусов остаётся отдельной семантической операцией.

## Порядок объяснения Adapter
Конкретная запись p-42, ожидаемая Receipt, клиент, связывающий их LegacyAdapter и пример запуска вводятся до подробностей Pydantic/Decimal. Путь вызова описан явно. Таблица до/после связывает методы, сумму и статус; каждый шаг содержит до 12 непустых строк.

## Зависимости
Версия Pydantic закреплена в метаданных исполняемых скриптов. uv запускает файл напрямую; запуск через python пропустил бы эти метаданные. unittest получает зависимость через uv --with. Сборщик читает AST и не импортирует учебные SDK. Новый корневой пакетный scaffold не требуется.
