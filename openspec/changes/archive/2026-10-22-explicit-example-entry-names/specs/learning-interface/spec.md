## MODIFIED Requirements

### Requirement: Понятные имена учебных файлов
Все25 тем MUST использовать имена ролевых модулей, раскрывающие их содержимое и обязанность. Файлы расширений MUST NOT называться extra.py. Входы с паттерном MUST называться with_pattern.py и with_pattern_extended.py; исходные решения MUST называться without_pattern.py и without_pattern_extended.py. Одинаковый суффикс MUST обозначать расширенный вариант обеих сторон. Переименование MUST обновлять импорты, команды, подписи и ссылки на исходники; прежние имена в ссылках полной реализации MUST открывать соответствующий переименованный файл без дополнительных файлов-обёрток.

#### Scenario: Чтение состава примера
- **WHEN** читатель выбирает файл полной реализации любой темы
- **THEN** его имя описывает обязанность роли либо однозначно обозначает сторону сравнения и базовый или расширенный запуск

#### Scenario: Прежнее имя
- **WHEN** ссылка полной реализации содержит прежнее имя переименованного файла
- **THEN** открывается тот же файл под актуальным именем

### Requirement: Минимальный учебный пример
Каждая глава MUST показывать механику паттерна и одно расширение двумя короткими парными сравнениями. Запуск MUST использовать нейтральные значения и минимум действий, необходимых для свойства паттерна. Бизнес-логика и произвольная валидация MUST отсутствовать. Читаемость и явные типы MUST сохраняться; разделение файлов MUST помогать пониманию обязанности или зависимости, а связанные короткие реализации MAY оставаться вместе.

#### Scenario: Чтение короткого примера
- **WHEN** открыта вкладка примеров
- **THEN** видны ровно две пары: основная операция и одно расширение

#### Scenario: Минимальный запуск
- **WHEN** открыт with_pattern.py
- **THEN** нейтральные значения показывают только существенные вызовы паттерна

## ADDED Requirements

### Requirement: Лаконичный diff расширения
Полная реализация расширения MUST предлагать один компактный переключатель изменений для обеих сторон. Изменения MUST сравниваться с базовой версией той же стороны; разные имена входов MUST NOT мешать сравнению. Добавленные строки MUST иметь мягкую зелёную подсветку и знак плюс, удалённые — красную и минус. Обычный полный исходник MUST оставаться доступным, копирование MUST всегда возвращать текущий исполняемый код без удалённых строк и diff-маркеров. Управление MUST работать с клавиатуры и в обеих темах.

#### Scenario: Изменённый запуск
- **WHEN** выбран расширенный вход с паттерном и включены изменения
- **THEN** показано его отличие от базового входа с паттерном, а не весь файл как новый

#### Scenario: Копирование diff
- **WHEN** пользователь нажимает копирование в режиме изменений
- **THEN** копируется полный текущий исполняемый файл, совпадающий с обычным режимом

#### Scenario: Неизменённая роль
- **WHEN** выбран общий ролевой файл без изменений
- **THEN** его строки не отмечаются как добавленные или удалённые
