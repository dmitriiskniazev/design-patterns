## MODIFIED Requirements

### Requirement: Разбор расширенных заданий
Каждая готовая тема MUST показывать ровно одно абстрактное расширение: новое поведение, участника, операцию или реализацию. Разбор MUST указывать изменённые и стабильные файлы и неизбежные изменения подключения. Короткие фрагменты MUST содержать не более12 непустых строк; масштабирование MUST означать рост вариантов, а не обещание ускорения.

#### Scenario: Из упражнения к разбору
- **WHEN** выбрано упражнение главы
- **THEN** открывается одно расширение той же абстрактной операции

#### Scenario: Сравнение до и после
- **WHEN** сравнивается расширение
- **THEN** видны прежний контракт, новый участник и точка его подключения

#### Scenario: Исполнение расширения
- **WHEN** выполняются две стороны расширения
- **THEN** вывод совпадает при одной новой абстрактной возможности

### Requirement: Содержательные учебные задачи
Готовые уроки MUST использовать абстрактные программные операции без предметных сюжетов, бизнес-правил и валидации ради демонстрации. Теория MUST объяснять обязанности, вызовы, заменяемые части и ограничения на нейтральных значениях1/A/B.

#### Scenario: Изучение рабочего сценария
- **WHEN** открывается глава
- **THEN** роли, вход и результат понятны без предметного сюжета

#### Scenario: Проверка границ
- **WHEN** проверяются свойства паттерна
- **THEN** тесты подтверждают независимость, идентичность или направление вызовов на нейтральных значениях

### Requirement: Прозрачный путь адаптации
Разбор Adapter MUST показывать ожидаемый клиентом интерфейс, несовместимую операцию Adaptee и перевод вызова адаптером. Все участники MUST быть локальными абстрактными объектами, без SDK, сети и единиц предметной области.

#### Scenario: Сквозной пример
- **WHEN** клиент вызывает operation адаптера
- **THEN** адаптер обращается к несовместимому методу Adaptee и возвращает ожидаемое значение

### Requirement: Ограниченная предметная область
Все25 тем MUST полностью исключать предметные модели и использовать канонические роли своего паттерна. Strategy MUST показывать подстановку операции в Context, Adapter — преобразование интерфейса, State — зависимость операции от текущего состояния, Observer — доставку обработчикам. Расширение MUST добавлять одну абстрактную возможность. Ролевые реализации и запуск MUST оставаться раздельными именованными файлами.

#### Scenario: Общая тема без лишних правил
- **WHEN** читатель переходит между темами
- **THEN** меняются только роли и устройство связей, а не предметная область

#### Scenario: Чтение и запуск файлов
- **WHEN** скопированы перечисленные файлы версии
- **THEN** указанная uv-команда запускает её без соседних файлов

### Requirement: Полнота учебного набора
Каждая тема MUST иметь четыре исполняемых набора: базовый и расширенный без паттерна и с паттерном. Наборы MUST быть автономными после копирования перечисленных файлов, демонстрировать свойство паттерна, иметь pytest-проверки, упражнение, схему и вопрос для собеседования.

#### Scenario: Самостоятельный запуск комплекта
- **WHEN** версия помещена в отдельный каталог
- **THEN** её точка входа и локальные зависимости достаточны для запуска

#### Scenario: Проверка существенного свойства
- **WHEN** запускается pytest темы
- **THEN** подтверждается свойство паттерна независимо от общего одинакового вывода

### Requirement: Постановка задачи в основном курсе
Глава MUST начинаться с цели абстрактной операции, входного значения, инварианта и ожидаемого результата. Затем MUST следовать простое решение, изменение требований и идея паттерна.

#### Scenario: Первое чтение State
- **WHEN** открыта глава State
- **THEN** показаны абстрактные состояния и их разные реакции на одну операцию

#### Scenario: Прямой вход в разбор
- **WHEN** открыта ссылка на примеры
- **THEN** пояснение называет роли, вход и результат без предметных предпосылок

#### Scenario: Первое чтение Strategy
- **WHEN** открыта глава Strategy
- **THEN** показана подстановка функции в Context с нейтральным входным числом

### Requirement: Архитектурные границы роста
Каждый паттерн MUST объяснять заменяемую часть, неизменяемых участников, точку подключения и цену абстракции. Расширение MUST проверяться запуском обеих версий. Заявленные стабильными файлы MUST действительно оставаться неизменными. Простой корректный вариант и функциональная альтернатива MUST NOT искусственно ухудшаться.

#### Scenario: Strategy
- **WHEN** добавляется новая стратегия
- **THEN** Context и контракт операции остаются прежними; новое подключение явно показано

#### Scenario: Adapter
- **WHEN** добавляется несовместимая реализация
- **THEN** клиент сохраняет ожидаемый интерфейс и получает отдельный адаптер

#### Scenario: State
- **WHEN** добавляется состояние
- **THEN** новый класс и входящий переход показаны как отдельные изменения

#### Scenario: Observer
- **WHEN** добавляется обработчик
- **THEN** Subject или Publisher продолжает доставку через прежний контракт

### Requirement: Термины и причины дизайна
Каждая глава MUST раскрывать употребляемые термины и причины выделения ролей перед сравнениями. Абстрактные имена MUST обозначать обязанности, а не произвольные ClassA/ClassB. Закрытый выбор MUST использовать StrEnum и match; свободные символические результаты MUST оставаться обычными строками.

#### Scenario: Чтение Adapter
- **WHEN** читатель встречает Target и Adaptee
- **THEN** роли интерфейсов и причина перевода вызова объяснены до кода

#### Scenario: Чтение Strategy
- **WHEN** читатель открывает Context
- **THEN** видит, что он вызывает переданную операцию и не знает списка реализаций

### Requirement: Связи полного исходника
Полная реализация MUST показывать назначение файла и ссылки на его локальные зависимости. Смена режима MUST открывать входные файлы обеих сторон. Прямая ссылка MUST выбирать существующий файл; отсутствующее прежнее имя MUST заменяться актуальным входным файлом. Код и список MUST помещаться в ширину страницы с локальной прокруткой кода.

#### Scenario: Чтение Strategy
- **WHEN** читатель открывает Context
- **THEN** видит, что он вызывает переданную операцию и не знает списка реализаций

#### Scenario: Восстановление ссылки
- **WHEN** открыта старая ссылка с отсутствующим именем
- **THEN** выбран входной файл актуальной абстрактной версии

### Requirement: Точные наборы сравнения
Все25 тем MUST предоставлять четыре явных набора с полным замыканием локальных импортов. Расширение MUST точно заменять или дополнять базовые файлы без посторонних реализаций другой стороны. Реестр одинаковых исходников MUST быть дедуплицированным.

#### Scenario: Расширение Decorator
- **WHEN** подключается новый декоратор
- **THEN** видны новый участник, сборка вложения и прежний контракт Component

#### Scenario: Общий файл
- **WHEN** обе стороны выбирают одинаковый полный файл
- **THEN** его исходник отображается один раз

### Requirement: Наблюдаемый выигрыш Strategy
Strategy MUST демонстрировать передачу новой функции либо объекта операции в неизменённый Context. Материал MUST признавать, что фиксированный короткий match проще при отсутствии роста. Подмена match на if MUST NOT объявляться архитектурным улучшением.

#### Scenario: Новый алгоритм вне встроенного списка
- **WHEN** Context получает новую функцию
- **THEN** он выполняет её через прежний контракт без регистрации в Context

#### Scenario: Выбор простого решения
- **WHEN** известна одна короткая фиксированная операция
- **THEN** глава признаёт прямую функцию более простой альтернативой

### Requirement: Явный переход к расширению
Переключение режима MUST открывать входные файлы выбранных версий обеих сторон. Расширение MUST показывать конкретное абстрактное требование и ссылки на новые или изменённые файлы. Прямая ссылка на неизменённый файл MUST сохранять его и объяснять неизменность со ссылками на изменения.

#### Scenario: Переключение с перечисления Strategy
- **WHEN** режим меняется после выбора произвольного файла Strategy
- **THEN** открываются точки входа выбранного режима, а не прежний модуль

#### Scenario: Прямая ссылка на неизменённый файл
- **WHEN** выбран неизменённый участник расширения
- **THEN** показаны пояснение неизменности и ссылки на новое подключение

#### Scenario: Расширение Decorator
- **WHEN** подключается новый декоратор
- **THEN** видны новый участник, сборка вложения и прежний контракт Component

### Requirement: Равноправные простые примеры
Обе стороны MUST использовать одинаковые абстрактные входы, возможности и результаты. Исходное решение MUST оставаться корректным без искусственно потерянных копий, истории, кеша или возможностей Python. Оно MUST NOT зависеть от инфраструктуры паттерна; независимые общие данные допустимы. Польза MUST объясняться структурой вызовов, зависимостями и расширением, с явным признанием простых альтернатив.

#### Scenario: История и кеш
- **WHEN** сравниваются Command либо Proxy
- **THEN** соответствующие возможности истории или кеширования совпадают на нейтральных значениях

#### Scenario: Снимки
- **WHEN** после создания снимка меняется Originator
- **THEN** восстановление возвращает прежнее значение в обеих версиях

#### Scenario: Независимый исходный вариант
- **WHEN** скопированы только файлы версии без паттерна
- **THEN** она выполняется без инфраструктуры противоположной стороны

#### Scenario: Составное поведение
- **WHEN** составляются участники либо выражения
- **THEN** обе версии получают одинаковый результат; роли показывают способ композиции

### Requirement: Минимальный учебный пример
Каждая глава MUST показывать механику паттерна и одно расширение двумя короткими парными сравнениями. Запуск MUST использовать нейтральные значения и минимум действий, необходимых для свойства паттерна. Бизнес-логика и произвольная валидация MUST отсутствовать. Читаемость, явные типы и разделение файлов MUST сохраняться.

#### Scenario: Чтение короткого примера
- **WHEN** открыта вкладка примеров
- **THEN** видны ровно две пары: основная операция и одно расширение

#### Scenario: Минимальный запуск
- **WHEN** открыт main.py
- **THEN** нейтральные значения показывают только существенные вызовы паттерна


### Requirement: Понятные имена учебных файлов
Все25 тем MUST использовать имена ролевых модулей, раскрывающие их содержимое и обязанность. Файлы расширений MUST NOT называться extra.py. Точки запуска MUST называться main.py и run_extended.py; исходные решения MUST называться without_pattern.py и without_pattern_extended.py. Переименование MUST обновлять импорты, команды, подписи и ссылки на исходники; прежние имена в ссылках полной реализации MUST открывать соответствующий переименованный файл.

#### Scenario: Чтение состава примера
- **WHEN** читатель выбирает файл полной реализации любой темы
- **THEN** его имя описывает обязанность роли либо однозначно обозначает запуск или вариант без паттерна

#### Scenario: Прежнее имя
- **WHEN** ссылка полной реализации содержит прежнее имя переименованного файла
- **THEN** открывается тот же файл под актуальным именем
