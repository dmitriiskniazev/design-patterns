## MODIFIED Requirements

### Requirement: Подсветка и копирование
Подсветка кода MUST работать без доступа к сети и следовать общей светлой или тёмной теме страницы; отображаемые фрагменты и копируемый текст MUST совпадать с соответствующими частями исходника. При отказе копирования MUST показываться понятное действие восстановления.

#### Scenario: Копирование исходника
- **WHEN** пользователь копирует текущий фрагмент
- **THEN** буфер содержит точный исходный текст фрагмента без разметки подсветки

#### Scenario: Отказ буфера обмена
- **WHEN** копирование недоступно
- **THEN** интерфейс сообщает об этом и предлагает выделить и скопировать показанный текст

### Requirement: Разделы и постоянные ссылки
Интерфейс MUST вести читателя по единой последовательности: задача и мотивация, базовое решение по шагам, самостоятельная практика, расширенное решение по шагам, следующая готовая тема. На каждом экране MUST быть один следующий переход и обратный переход, кроме границ курса. Прогресс MUST показывать положение в этой последовательности. Вкладки разделов, список переходов между шагами и переходы из схемы MUST NOT конкурировать с основным чтением. Прямые ссылки MUST сохранять тему, раздел и шаг; история браузера MUST работать. Выбор темы в каталоге MUST открывать её начало. Strategy, Adapter, State и Observer MUST показывать одну страницу сравнения в основном курсе; ссылки прежних кода, практики и расширения MUST вести в соответствующую часть этой страницы.

#### Scenario: Возврат к разделу
- **WHEN** открывается ссылка готового урока или используется история браузера
- **THEN** восстанавливаются выбранные тема и место чтения; в четырёх темах сравнения шаг соответствует смысловой части полной страницы

#### Scenario: Ошибочная ссылка
- **WHEN** идентификатор темы или формат ссылки некорректен
- **THEN** интерфейс открывает доступный материал Strategy без ошибки выполнения

#### Scenario: Конец расширения
- **WHEN** пользователь завершает последний шаг расширения
- **THEN** следующий переход открывает начало следующей готовой темы, а после последней темы показано завершение курса без возврата к практике

#### Scenario: Начало другой темы
- **WHEN** пользователь выбирает другую тему из каталога, находясь на шаге расширения
- **THEN** открывается постановка новой темы, а не расширение

### Requirement: Постепенное представление кода
Каждый готовый урок MUST вводить конструкции через последовательность шагов: короткое пояснение, листинг не длиннее 12 непустых строк и объяснение результата. В пошаговых темах на экране MUST отображаться один шаг с навигацией назад и вперёд. Strategy, Adapter, State и Observer MUST показывать полные именованные файлы сравнения, включая импорты и запуск. Ограничение 12 строк относится к объясняющим фрагментам, а не к полным файлам. Интерфейс MUST NOT требовать скачивания.

#### Scenario: Чтение по шагам
- **WHEN** пользователь открывает код и переходит к следующему шагу
- **THEN** в пошаговой теме отображается следующий короткий листинг; в теме сравнения сразу видны полные файлы обеих версий

#### Scenario: Отдельный исполняемый файл
- **WHEN** пользователь копирует файлы полного примера
- **THEN** получает исполняемый набор с импортами и точкой запуска

### Requirement: Собранный код доступен для чтения
Пользователь MUST иметь возможность посмотреть полный итоговый комплект Python-файлов на странице отдельно от коротких шагов. Показанный текст MUST совпадать с соответствующим файлом исполняемого комплекта; код MUST соответствовать предметной теме урока и поддерживать локальное чтение. В пошаговых темах полный код MUST открываться по выбору пользователя. В четырёх темах сравнения код MUST сразу показываться по файлам в колонках. Интерфейс MUST NOT предлагать скачивание.

#### Scenario: Чтение итогового файла
- **WHEN** пользователь выбирает просмотр собранного кода
- **THEN** видит полные файлы под раскрытием в пошаговой теме или непосредственно в колонках темы сравнения

#### Scenario: Сохранение постепенного формата
- **WHEN** пользователь открывает шаг без выбора полного файла
- **THEN** в пошаговой теме отображается короткий листинг, а в теме сравнения — полный код по файлам

### Requirement: Последовательное изложение урока
В пошаговых темах теория MUST излагаться одной колонкой в порядке: задача, простое решение, новое требование, идея паттерна, участники и путь вызова, условия применения и цена. Схема MUST следовать после мотивации, не повторяться на каждом базовом шаге и не вводить переходов между шагами. Дублирующий список ролей и предварительный первый листинг MUST NOT разрывать этот порядок. Каждый экран пошаговой темы MUST сохранять один короткий листинг и пояснение. В четырёх темах сравнения MUST последовательно показываться применение, две реализации, одно новое требование и границы выигрыша. Итоговый комплект и просмотр полных файлов MUST предлагаться после последнего шага соответствующего разбора.

#### Scenario: Первое чтение любой темы
- **WHEN** пользователь последовательно проходит готовый урок
- **THEN** сначала узнаёт задачу; затем проходит шаги в пошаговой теме или сравнивает две реализации и их расширения в теме сравнения

#### Scenario: Прямой вход в код
- **WHEN** пользователь открывает первый базовый или расширенный шаг по ссылке
- **THEN** видит постановку перед текущим листингом; дальнейший переход продолжает общий порядок

## ADDED Requirements

### Requirement: Сравнение решений в основном курсе
Strategy, Adapter, State и Observer MUST показывать версии без паттерна и с паттерном рядом на широком экране и последовательно на узком. Каждая версия MUST состоять из именованных файлов с полным кодом, включая импорты и запуск. Для одинаковых входов вывод MUST совпадать. После нового требования MUST показываться полные изменённые и новые файлы обеих сторон с указанием неизменённых файлов. Код MUST собираться из исполняемых исходников проекта. Основной вход web/index.html MUST показывать этот формат без временного макета. Для этих тем прежние требования отдельного шага и скрытого полного кода заменяются сравнением полных файлов.

#### Scenario: Обычный вход
- **WHEN** пользователь выбирает одну из четырёх тем в основном курсе
- **THEN** сразу видит сравнение и полные файлы без скачивания

#### Scenario: Расширение
- **WHEN** пользователь читает новое требование
- **THEN** видит изменения обеих версий, а точки подключения и тесты не объявляются неизменными без основания
